# Implementation Roadmap & Acceptance Criteria

Each phase ends with: tests passing (`pnpm test`, `cargo test`), lint/typecheck clean, and an independent review pass (not just the implementing subagent's own report) before moving on.

| #   | Phase                       | Status      | Key acceptance criteria                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --- | --------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2   | Project init                | Done        | `pnpm dev` launches a Tauri window; empty SQLite DB created + first migration applied; `ci.yml` runs and passes on an empty test suite.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 3   | Core data                   | Done        | Full CRUD (via Tauri commands + UI forms) for raw materials, suppliers, purchase records; price history never overwritten (append-only verified by test); login/logout works with Argon2id; invalid input rejected with field-level errors.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 4   | Costing engine              | Done        | All scenarios in `costing-engine.md` §5 covered by passing unit tests (54 tests, `packages/core`); nested-recipe example from §12 reproduces the exact documented numbers; cycle detection rejects a constructed A→B→A case with a descriptive error. Recipe CRUD + nested ingredients + cost breakdown UI verified live in the running app.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 5   | UI                          | Done        | Dashboard + all 8 nav sections navigable (sidebar shell, shadcn/ui + Tailwind CSS per docs/architecture.md); recipe cost breakdown screen matches the §12.4 table format; destructive actions (archive/delete) require confirmation via AlertDialog. Also added: light/dark theme toggle, an architecture-ready (English-only) i18n scaffold, and a User Profile change-password flow.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 6   | Local backup                | Done\*      | Create/list/restore backup round-trips a non-trivial DB losslessly (verified by test: create data → backup → wipe DB → restore → assert data identical); restore takes a pre-restore safety backup automatically; corrupted/tampered backup file is rejected with a clear error, not a crash. All three verified by automated Rust tests (66 total). \*UI code-reviewed and confirmed to launch cleanly; interactive click-through (create/restore via the running app) deferred to the user's own convenience, not yet done as of this note.                                                                                                                                                                                                                                                                                                           |
| 7   | Cloud (Dropbox)             | Done\*\*    | OAuth PKCE flow completes end-to-end against a real Dropbox test account; upload/list/download/delete all exercised by an integration test (or clearly marked manual test script if CI can't hold live OAuth secrets); Google Drive stub documented, not silently half-working. Upload/list/download/delete/retry/auth-failure fully covered by mocked-HTTP-server integration tests (16 of 82 Rust tests) — PKCE itself verified against a known-good RFC 7636 test vector. \*\*Live OAuth against a real Dropbox account is genuinely not yet done: by the user's own choice (see docs/backup-and-updates.md §2b), no Dropbox app has been registered yet, so `dropbox_connect` has never been exercised against real Dropbox servers. Code is complete and reviewed; this is an honest gap, not an oversight — revisit once an App Key is available. |
| 8   | CI/CD & packaging           | Not started | A tagged pre-release produces installable artifacts for Windows, macOS, and Linux from GitHub Actions; artifacts actually install and launch on each OS (verified manually at least once before calling this done).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 9   | Auto-updates                | Not started | A test release with an intentionally lower version number is detected as "update available" by a build with a higher version; a tampered `latest.json`/binary is rejected by signature check; toggling all three update settings off/on behaves as documented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 10  | Security & final validation | Not started | `cargo audit` / `pnpm audit` clean or issues triaged and documented; no secrets in git history; final report delivered per requirement §27.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Phase 1 (this document set) and its risk items are the only gate before Phase 2 begins.
